## 🔐 Authentication APIs

### `POST /api/auth/login`

> Sets an HttpOnly session cookie on success.

**Request Body**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `email` | `string` | ✅ | User email address |
| `password` | `string` | ✅ | User password |
| `remember` | `boolean` | ❌ | Extend session to 30 days (default: 7 days) |

```json
{
  "email": "user@example.com",
  "password": "123456",
  "remember": true
}
```

**Responses**

| Status | Body |
|--------|------|
| `200 OK` | `{ "redirectTo": "/dashboard" }` |
| `401 Unauthorized` | `{ "error": "Invalid email or password" }` |

**Cookie set on success**

| Property | Value |
|----------|-------|
| Name | `rayyan_session` |
| Algorithm | HS256 (via `jose`) |
| Payload | `{ email, role: "user" }` |
| HttpOnly | ✅ |
| Expiry (`remember=false`) | 7 days |
| Expiry (`remember=true`) | 30 days |

**Demo credentials** (development only)

| Email | Password |
|-------|----------|
| `user@example.com` | `123456` |

---

### `POST /api/auth/logout`

> Clears the session cookie.

**Request Body**: _empty_

**Responses**

| Status | Body |
|--------|------|

**Effect**: Sets `rayyan_session` cookie `maxAge` to `0`. Client redirects to `/login`.

## 🤖 AI Proposal Generation

> Rayyan uses AI to automatically generate proposal content from uploaded RFP documents and metadata. The generation is **asynchronous** — submit a job, then poll for its status.

### Flow Overview

```
User fills wizard steps 1–3 (or uses ProposalDetailsModal)
  └─► POST /api/proposals/generate   { metadata, rfpFiles, documents }
        └─► 202 Accepted  →  { jobId: "job_abc123" }

Client polls:
  GET /api/proposals/generate/:jobId/status
    ├── status: "queued"     →  keep polling
    ├── status: "processing" →  show progress to user
    ├── status: "completed"  →  { proposalId, previewUrl }
    └── status: "failed"     →  { error: "..." }
```

---

### `POST /api/proposals/generate` _(not yet created)_

> Submits all wizard data for AI-powered proposal generation.

**Request**: `multipart/form-data`

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `clientName` | `string` | ✅ | Client / organization name |
| `projectName` | `string` | ✅ | Name of the project |
| `proposalLanguage` | `"ar"` \| `"en"` | ✅ | Output language |
| `sectorIndustry` | `string` | ✅ | Sector / industry domain |
| `proposalType` | `string` | ✅ | e.g. `"Technical"`, `"Financial"` |
| `startDate` | `string (ISO)` | ❌ | Project start date |
| `endDate` | `string (ISO)` | ❌ | Project end date |
| `additionalDetails` | `string` | ❌ | Free-text context or requirements |
| `rfpFiles` | `File[]` | ❌ | RFP documents uploaded from system |
| `rfpDatabaseIds` | `string[]` | ❌ | IDs of RFP docs selected from database |
| `sections[].title` | `string` | ❌ | Timeline card title (Step 2) |
| `sections[].period` | `string` | ❌ | e.g. `"Week 1–3"` (Step 2) |
| `sections[].chips` | `string[]` | ❌ | Optional section component labels (Step 2) |
| `resumeFiles` | `File[]` | ❌ | Team CV/resume documents (Step 3) |
| `teamFiles` | `File[]` | ❌ | Team profile documents (Step 3) |
| `certificateFiles` | `File[]` | ❌ | Certificates and registrations (Step 3) |
| `otherFiles` | `File[]` | ❌ | Other supporting documents (Step 3) |
| `companyDocIds` | `string[]` | ❌ | IDs of company docs from database |
| `aiPrompt` | `string` | ❌ | Optional user prompt guiding AI tone/focus |

> ℹ️ At least one of `rfpFiles` or `rfpDatabaseIds` should be provided for meaningful AI generation.

**Response `202 Accepted`**

```json
{
  "jobId": "job_abc123",
  "estimatedSeconds": 30,
  "message": "Proposal generation started"
}
```

**Response `400 Bad Request`**

```json
{
  "error": "Validation failed",
  "fields": { "clientName": "Required", "proposalLanguage": "Required" }
}
```

---

### `GET /api/proposals/generate/:jobId/status` _(not yet created)_

**Response**

```json
{
  "jobId": "job_abc123",
  "status": "processing",
  "progress": 60,
  "message": "Analyzing RFP documents..."
}
```

| `status` | Meaning |
|----------|---------|
| `queued` | Waiting in AI queue |
| `processing` | AI is actively generating |
| `completed` | Ready — fetch the result |
| `failed` | Generation failed |

**When `status = "completed"`**

```json
{
  "jobId": "job_abc123",
  "status": "completed",
  "proposalId": "prop_xyz",
  "previewUrl": "/dashboard/proposals/prop_xyz"
}
```

| Code | Language | Direction |

**Files**

| File | Purpose |

**RTL support**: Layout direction switches globally via `dir` attribute on `<html>`. Tailwind logical properties (`ps-`, `pe-`, `ms-`, `me-`, `border-s`, `border-e`) are used throughout for bidirectional layout.
